# 07. Долговременная память

> Статус: **спроектировано, не реализовано.** В коде есть только рабочая
> память (буфер латентов внутри `Engine`). Остальное — спецификация.

## 1. Коротко

У предиктора JEPA нет состояния: это функция `(z, a) → ẑ'`. Всё, что система
«помнит», живёт либо в весах (медленно, размыто), либо во внешнем хранилище
(быстро, точно, но требует поиска).

Контекстное окно трансформера — **не память**. Это буфер фиксированного
размера, который:

* переполняется (и тогда старое выбрасывается);
* не индексируется по смыслу;
* не переживает перезапуск;
* стоит `O(L²)` по вниманию.

Поэтому память — отдельный модуль с отдельными гарантиями.

---

## 2. Три уровня

```
┌─────────────────────────────────────────────────────────────┐
│ РАБОЧАЯ (working)                                           │
│   что: последние N латентов z, действий a, ошибок surprise  │
│   где: RAM, кольцевой буфер                                 │
│   время жизни: секунды                                      │
│   доступ: O(1)                                              │
└───────────────────────────┬─────────────────────────────────┘
                            │ каждый шаг
┌───────────────────────────▼─────────────────────────────────┐
│ ЭПИЗОДИЧЕСКАЯ (episodic)                                    │
│   что: (z, t, контекст, действие, surprise, исход)          │
│   где: векторный индекс (HNSW/FAISS) + метаданные           │
│   время жизни: дни-недели                                   │
│   доступ: O(log N) приближённый поиск                       │
└───────────────────────────┬─────────────────────────────────┘
                            │ «сон» / консолидация
┌───────────────────────────▼─────────────────────────────────┐
│ СЕМАНТИЧЕСКАЯ (semantic)                                    │
│   что: обобщённые закономерности                             │
│   где: веса предиктора и энкодера                           │
│   время жизни: постоянно                                    │
│   доступ: один forward                                      │
└─────────────────────────────────────────────────────────────┘
```

Аналогия с человеком: рабочая память — то, что вы держите в голове сейчас;
эпизодическая — воспоминания о конкретных событиях; семантическая — знания
(«лёд скользкий»), которые вы уже не помните, откуда взяли.

---

## 3. Рабочая память

### 3.1 Что хранится

```python
@dataclass
class WorkingMemory:
    z: deque[torch.Tensor]        # (D,) на шаг, maxlen=N
    a: deque[torch.Tensor]        # (A,)
    surprise: deque[float]        # скаляр на шаг
```

`N` — 32–256 шагов. Больше не нужно: предиктор всё равно не использует
историю глубже, если не обучен на это.

### 3.2 Зачем

* **Сглаживание предсказаний.** Один шумный кадр не должен ломать оценку
  состояния — можно взять медиану по последним `k` латентам.
* **Оценка surprise.** Нужен предыдущий латент и действие.
* **Быстрый recall.** Если текущий `z` близок к недавнему, можно не
  перепланировать.

### 3.3 Ограничение

Рабочая память **не даёт** долгосрочных зависимостей. «Я уже видел эту
комнату час назад» — это эпизодическая память.

---

## 4. Эпизодическая память

### 4.1 Запись

Каждые `k` шагов (или при `surprise > τ`) сохраняем запись:

```python
@dataclass
class Episode:
    key: torch.Tensor        # (D,) латент — используется для поиска
    value: dict              # что именно запомнить
    t: float                 # время
    surprise: float          # насколько неожиданно
    outcome: float | None    # чем закончилось (если известно)
```

`value` может содержать:

* латент цели, если она была;
* последовательность действий;
* текстовое описание (если есть языковой мост);
* флаг успеха/провала.

### 4.2 Что писать, а что нет

Наивная стратегия «писать всё» упирается в объём: 10 Гц × 8 часов = 288 000
записей в день. Поэтому — фильтр по важности:

| Критерий | Зачем |
|---|---|
| `surprise > τ` | новое или аномальное |
| успех/провал задачи | учиться на исходах |
| редкое состояние (далеко от центроида) | покрытие пространства |
| запрос пользователя | «запомни это» |

Остальное — выбрасывается. Это не потеря: обычные состояния и так выучены
в весах.

### 4.3 Поиск

Запрос — латент `z_q`. Ищем `k` ближайших по евклидову расстоянию (или
косинусу). Индекс — HNSW: `O(log N)` на запрос, обновление онлайн.

Почему не «по времени»: нужен доступ по **содержанию**, а не по хронологии.
«Где я видел такую конфигурацию?» — типичный запрос.

### 4.4 Как использовать результат

Три способа:

1. **Как цель.** Найденный эпизод с успешным исходом даёт `z_goal` для
   планировщика: «в прошлый раз, когда я был здесь, надо было сделать так».
2. **Как ограничение.** Найденный эпизод с провалом даёт «не делай так»:
   штраф за близость к траектории провала.
3. **Как контекст для языка.** Найденные эпизоды передаются в LLM для
   объяснения: «я делаю это, потому что в 14:32 была похожая ситуация».

## 5. Семантическая память: консолидация

### 5.1 Идея

Эпизодическая память хранит **случаи**. Семантическая — **закономерности**.
Переход — через обучение: берём эпизоды, проигрываем их через модель,
делаем шаги градиента.

Это буквально то, что происходит во сне: гиппокамп «проигрывает» эпизоды,
а кора впитывает статистику.

### 5.2 Процедура

```python
def consolidate(model, memory, n_steps=1000):
    for _ in range(n_steps):
        # 1. приоритет — эпизоды с высоким surprise и известным исходом
        batch = memory.sample_prioritized(n=32)
        # 2. проиграть и посчитать обычную JEPA-потерю
        loss = jepa_loss(model, batch.frames, batch.actions)
        # 3. шаг градиента
        loss.backward(); opt.step()
        # 4. понизить приоритет обработанных
        memory.decay_priority(batch.ids)
```

### 5.3 Катастрофическое забывание

Главная опасность: дообучение на новых эпизодах стирает старое. Меры:

| Метод | Суть |
|---|---|
| **replay** | смешивать новые эпизоды со старыми (буфер) |
| **EWC** | штраф за изменение важных весов |
| **LoRA-адаптеры** | не трогать базовые веса, учить маленькие добавки |
| **дистилляция** | сохранять выходы старой модели на эталонных входах |

Для JEPA самый естественный — replay + LoRA: базовый энкодер замораживается,
адаптеры учат новое.

## 6. Почему не «просто длинный контекст»

Может показаться, что достаточно увеличить контекстное окно. Это не работает
по четырём причинам:

1. **Стоимость.** Внимание `O(L²)`; 10 часов при 10 Гц — 360 000 токенов.
2. **Нет индексации.** Нельзя спросить «покажи похожее», только «покажи
   предыдущее».
3. **Размывание.** Модель плохо использует середину длинного контекста
   («lost in the middle»).
4. **Нет персистентности.** Перезапуск — и всё забыто.

Память — это **база данных с индексом по смыслу**, а не буфер.

## 7. Интерфейс (спецификация)

```python
class Memory:
    def write(self, z, action, surprise, outcome=None, meta=None) -> int: ...
    def query(self, z, k=5, filter=None) -> list[Episode]: ...
    def consolidate(self, model, steps=1000) -> dict: ...
    def stats(self) -> dict: ...
```

Требования:

* `write` — `O(1)` амортизированно, потокобезопасно;
* `query` — `O(log N)`, возвращает `k` ближайших;
* `consolidate` — асинхронно, не блокирует основной цикл;
* персистентность — запись на диск батчами, восстановление после падения.

---

## 8. Как измерять память

Метрики, без которых «память» — это маркетинг:

| Метрика | Что измеряет |
|---|---|
| **Recall@k** | доля запросов, где нужный эпизод попал в топ-k |
| **Успех на отложенных задачах** | задачи, решаемые только с памятью |
| **Деградация после консолидации** | насколько упало качество на старых задачах |
| **Объём/запись** | сколько занимает и сколько стоит запись |
| **Латентность запроса** | p50/p99 |

Обязательный тест: **A-B-A**. Обучаем на A, потом на B, потом проверяем A.
Без памяти качество на A падает; с памятью — нет.
