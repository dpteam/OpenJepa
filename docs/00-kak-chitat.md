# 00. Как читать этот репозиторий

## Зачем нужна эта страница

Документация написана для двух очень разных читателей одновременно:

* **человек без ML-бэкграунда**, которому нужно понять, о чём вообще речь и
  почему это важно;
* **LM-инженер**, которому нужны формулы, размерности, гиперпараметры и
  подводные камни.

Один текст не может быть оптимален для обоих. Поэтому каждый документ устроен
одинаково:

```
┌─────────────────────────────────────────┐
│ 1. Коротко (5-7 строк)                  │  ← читают все
│ 2. Как это работает (аналогии)          │  ← читают все
│ 3. Детали и формулы                     │  ← инженеры
│ 4. Что это значит на практике           │  ← все
│ 5. Чеклист / что дальше                 │  ← все
└─────────────────────────────────────────┘
```

Если вы не инженер — читайте разделы 1, 2, 4 и пропускайте формулы. Ни одна
важная мысль не спрятана только в формулах.

## Соглашения

**Термины.** Первое упоминание термина даётся с расшифровкой и переводом.
Полный глоссарий — в конце этого файла.

**Числа.** Все числа из статей помечены ссылкой вида `[arXiv:2511.08544]`.
Числа без ссылки — либо из нашего кода (тогда указан конфиг), либо арифметика.

**Код.** Фрагменты в документах синхронизированы с `src/openjepa/`. Если
расходятся — прав код, документация считается багом.

**«Реализовано» vs «спроектировано».** В README есть таблица статусов.
Мы не пишем «сделано» про то, что не запускается.

## Глоссарий

| Термин | Что это | Аналогия |
|---|---|---|
| **JEPA** | Joint-Embedding Predictive Architecture — архитектура, которая предсказывает *эмбеддинг* будущего, а не сам вход | Вместо того чтобы рисовать, где окажется мяч, вы говорите: «он будет в правом верхнем углу, движется вправо-вниз» |
| **Эмбеддинг** | Вектор чисел, описывающий наблюдение | Координаты смысла: похожие вещи → близкие векторы |
| **Латентное пространство** | Пространство эмбеддингов, где живёт модель | Карта мира, на которой нет лишних деталей |
| **Энкодер** | Сеть «наблюдение → эмбеддинг» | Глаз + зрительная кора |
| **Предиктор** | Сеть «эмбеддинг сейчас + действие → эмбеддинг потом» | Мозжечок, который просчитывает траекторию |
| **SIGReg** | Регуляризатор, удерживающий эмбеддинги в виде изотропного гауссиана | Правило «не сваливай все смыслы в одну точку» |
| **Коллапс** | Вырождение: сеть выдаёт одинаковый вектор на всё | Студент, который на любой вопрос отвечает «не знаю» и получает ноль ошибок |
| **Модель мира** | Система, предсказывающая последствия действий | Внутренний симулятор |
| **Планирование в латенте** | Поиск действий через «воображение» последствий в пространстве эмбеддингов | Шахматист, который считает варианты в голове, а не на доске |
| **CEM** | Cross-Entropy Method — population-based оптимизация | Отбор: каждый раунд оставляем лучшие варианты и улучшаем их |
| **MPC** | Model Predictive Control — план + исполнение первого шага + перепланирование | Водитель, который каждые 100 м корректирует маршрут |
| **H-JEPA** | Иерархический JEPA: несколько уровней с разными временными масштабами | Стратег → тактик → рефлекс |
| **Surprise** | Ошибка предсказания: насколько реальность не совпала с ожиданием | «Так не должно было быть» |
| **Platonic representation** | Гипотеза, что разные модели сходятся к одному представлению реальности | Разные карты одной и той же местности |
| **Stop-gradient** | Трюк, при котором градиент не течёт в одну из ветвей | Костыль, от которого LeJEPA избавляется |
| **AGI** | Artificial General Intelligence — общий ИИ | См. `11-riski-i-predely.md`, там всё не так просто |
