# 05. Обучение: рецепт, математика, диагностика

## 1. Коротко

Обучение JEPA — это две силы, тянущие в противоположные стороны:

* **предсказание** тянет все эмбеддинги в одну точку (так проще предсказывать);
* **SIGReg** расталкивает их в изотропный гауссиан (так представление не
  вырождается).

Баланс задаётся одним числом `λ`:

```
L = (1 - λ) · L_pred + λ · SIGReg(Z)
```

Всё. Никаких stop-gradient, EMA-учителей, расписаний, клиппинга градиента
и подбора шести коэффициентов. Это главное практическое достижение LeJEPA
[arXiv:2511.08544].


## 3. SIGReg: как именно он работает

### 3.1 Задача

Дано: `N` эмбеддингов `z_1..z_N ∈ R^D`.
Требуется: чтобы их распределение было `N(0, I)`.

Наивный путь — сравнить выборочную ковариацию с `I`. Это работает плохо:

* моменты выше второго не контролируются;
* выборочная ковариация в `R^D` требует `O(D²)` памяти и шумит;
* распределение с `Cov = I` может быть сколь угодно не-гауссовым
  (например, «X»-образное, см. рис. 5 в статье).

### 3.2 Идея: проекции + критерий согласия

Вместо `D`-мерного сравнения берём `M` случайных единичных направлений
`a_1..a_M` и для каждого проверяем одномерную гипотезу:

```
H0(a): распределение (aᵀz) = N(0,1)
```

По **теореме Крамера–Вольда** (в усиленной, «гиперсферической» форме):

> `X =ᵈ Y` тогда и только тогда, когда `⟨u,X⟩ =ᵈ ⟨u,Y⟩` для всех `u` на
> единичной сфере.

То есть если **все** одномерные проекции совпали с гауссианом, совпало и
`D`-мерное распределение. На практике берут конечное `M`, и это даёт
корректную статистику с гарантиями (теорема 2 в статье).

### 3.3 Одномерный критерий: Эппс–Пули

Для проекции `u_i = aᵀz_i` строим эмпирическую характеристическую функцию:

```
φ̂_N(t) = (1/N) Σ_i exp(i t u_i)
```

и сравниваем с CF стандартного гауссиана `φ(t) = exp(-t²/2)`:

```
EP = N ∫ |φ̂_N(t) - φ(t)|² w(t) dt,     w(t) = exp(-t²/2)
```

Раскладывая на вещественную и мнимую части:

```
|φ̂ - φ|² = ( (1/N)Σ cos(t u_i) - e^{-t²/2} )² + ( (1/N)Σ sin(t u_i) )²
```

Ровно это и считается в `losses/sigreg.py`:

```python
x_t = (flat @ a).unsqueeze(-1) * t      # (N, M, K)
err = (x_t.cos().mean(0) - phi).square() + x_t.sin().mean(0).square()
statistic = (err @ weights) * n
```

### 3.4 Почему именно CF, а не моменты или CDF

| Семейство | Проблема |
|---|---|
| **моменты** (Jarque–Bera) | конечное число моментов не идентифицирует распределение; градиенты растут как `O(k)`, дисперсия как `O(k²)` → обучение взрывается |
| **CDF** (Колмогоров–Смирнов, Крамер–фон Мизес) | требует сортировки, `O(N log N)`, плохо параллелится, разрывные градиенты |
| **CF** (Эппс–Пули) | ограниченные значения и градиенты, `O(N)`, идеально для GPU |

Формально (теорема 4 в статье): градиент статистики по одному сэмплу ограничен

```
‖∂EP/∂z_i‖ ≤ 4σ²/N,    ‖∂²EP/∂z_i²‖ ≤ C√π σ³/(2N)
```

Это и есть причина, по которой обучение не требует клиппинга.

### 3.5 Почему это не «проклятие размерности»

Наивное сравнение распределений в `R^D` требует экспоненциально много данных.
Здесь сложность зависит от **гладкости** распределения эмбеддингов (коэффициенты
Соболева `α`), а не от `D`. Так как целевое распределение (гауссиан) очень
гладкое, эмбеддинги быстро становятся гладкими, и `M=256` направлений
достаточно даже при `D=1024`.

### 3.6 Итоговая формула

```
SIGReg(Z) = (1/M) Σ_m EP(a_mᵀ Z)
```

Усреднение, а не максимум — чтобы не было разреженных градиентов по
направлениям (в статье это оговорено отдельно).

## 4. Почему не BYOL / DINO / VICReg

| Метод | Anti-collapse | Гиперпараметры | Сложность | Теория |
|---|---|---|---|---|
| SimCLR | негативы | t°, batch | `O(N²)` | частичная |
| BYOL | stop-grad + EMA | EMA-расписание, τ | `O(N)` | постфактум |
| DINO | центрирование + EMA | momentum, center, τ | `O(N)` | постфактум |
| VICReg | variance + covariance | 3 коэффициента | `O(D²)` | частичная |
| Barlow Twins | кросс-корреляция | 1 коэффициент | `O(D²)` | частичная |
| **LeJEPA** | **SIGReg** | **1 коэффициент** | **`O(N)`** | **доказана оптимальность** |

«Постфактум» означает: метод работает, но объяснение появилось после, и оно
не предсказывает, когда метод сломается.

Практический выигрыш LeJEPA: **лосс коррелирует с downstream-качеством**
(Spearman > 0.94 по статье). Это значит, что можно делать model selection
без размеченной валидации — редкость в self-supervised обучении.

## 5. Рецепт обучения (как в коде)

### 5.1 Псевдокод

```python
for frames, actions in loader:               # (B,T,3,H,W), (B,T-1,A)
    z = projector(encoder(frames))           # (B,T,64)
    w = context_windows(z, ctx)              # (B,T,ctx,64) — окно прошлого
    pred = predictor(w[:, :-1], actions)     # (B,T-1,64)
    loss_pred = smooth_l1(pred, z[:, 1:])
    inv = inverse(z[:, :-1], z[:, 1:])       # (z_t, z_{t+1}) -> a_t
    loss_inv = smooth_l1(inv, actions)
    p_hat = probe(z)                         # z -> позиция (readout)
    loss_probe = smooth_l1(p_hat, positions)
    loss_metric = metric(z, positions)       # ‖Δz‖ ~ α·‖Δp‖
    loss_reg  = sigreg(z.float())
    loss = ((1-lamb) * (loss_pred + inv_weight*loss_inv)
            + lamb * loss_reg
            + metric_weight * loss_metric + probe_weight * loss_probe)
    loss.backward(); opt.step()
```

Три члена, у каждого своя роль:

| Член | Что заставляет модель делать |
|---|---|
| `loss_pred` | предсказывать будущее в латенте (основная цель) |
| `loss_inv` | сохранять в латенте то, на что влияет действие |
| `loss_probe` | сохранять в латенте физические координаты (readout) |
| `loss_metric` | делать латентное расстояние пропорциональным реальному |
| `loss_reg` | держать распределение эмбеддингов изотропно-гауссовым |

Без `loss_inv` модель выучивает «удобные» факторы и выбрасывает управляемые
(подробно: `03-arhitektura.md` §4.2.1).

### 5.2 Метрическая регуляризация

Планировщик считает стоимость как `‖z_t − z_goal‖²`. Это осмысленно только
если латентное расстояние пропорционально реальному. Ничто в
`pred_loss`/`SIGReg` этого не гарантирует — и на практике не выполняется.

Замер на нашем чекпоинте (без метрической регуляризации):

| сдвиг мяча | ‖Δz‖ |
|---|---|
| 0.5 px | 4.09 |
| 2.0 px | 11.18 |
| 40 px | ~18 |

Сдвиг в 80 раз больше даёт изменение латента всего в 4.4 раза. Планировщик
не различает «рядом» и «далеко».

Решение — требование **постоянства отношения** `‖Δz‖/‖Δp‖`:

```python
r = ‖z_i − z_j‖ / ‖p_i − p_j‖
loss_metric = std(r) / mean(r)      # коэффициент вариации
```

`p` — позиция объекта из симулятора. Это **привилегированная информация**:
доступна только при обучении, на инференсе не нужна. Тот же приём, что
inverse-dynamics с действиями.

**Почему коэффициент вариации, а не `|‖Δz‖ − α‖Δp‖|`.** Первая форма
безразмерна: её значение не зависит от масштаба латента, поэтому она не
конкурирует с SIGReg за дисперсию. Вторая форма в абсолютных единицах
доминирует над `pred_loss` (в нашем первом эксперименте давала 7.4 против
0.27) и разрушает обучение — проверено.

Форма безразмерная, поэтому «схлопнуть» латент в ноль нельзя: при
`‖Δz‖ → 0` числитель и знаменатель падают одновременно.

Важное следствие: регуляризация требует не просто монотонности, а
**изометрии с точностью до масштаба**. Анизотропное растяжение (разный
масштаб по осям) штрафуется — и это правильно, иначе одинаковый сдвиг по X
и по Y «стоил» бы для планировщика по-разному.

**На практике эта регуляризация у нас не заработала** и держится на
значении 1.0 (что соответствует полностью несвязанным величинам). Причина
— конфликт с SIGReg, см. §8 и `research/notes/2026-11-06-sigreg-vs-metric.md`.
Она оставлена как опция, но не является решением проблемы.

### 5.3 Проба: стоимость в пространстве задачи

Планировщик может считать стоимость двумя способами:

| режим | формула | что нужно |
|---|---|---|
| `latent` | `‖z_t − z_goal‖²` | латент должен быть метрикой, цель — состоянием |
| `probe` | `‖p̂(z_t) − p_goal‖²` | обученная проба `z → p` |

Второй режим честнее: цель — «объект в точке X», а не «объект в точке X с
нулевой скоростью». Проба — это **readout**, а не декодер картинки: пиксели
не восстанавливаются, только физические координаты.

Обучение пробы даёт побочную пользу: если она не может предсказать позицию,
значит латент её не содержит. Это диагностика, а не отдельная задача.

Две практические детали:

1. **Позиции надо нормировать в `[-1, 1]`.** Иначе потеря пробы (~30 в
   пикселях) доминирует над остальными членами (~0.1–1), и обучение
   разваливается. Проверено: `loss` был 34.
2. **Выход пробы инициализируется нулями.** При случайной инициализации на
   латенте с нормой ~5 проба выдаёт значения ~20, и её потеря снова
   доминирует. С нулевым выходом стартовая потеря ~0.1.

### 5.4 Гиперпараметры

| Параметр | Значение | Диапазон | Комментарий |
|---|---|---|---|
| `lr` | 3e-4 | 1e-4 … 2e-3 | AdamW, cosine |
| `weight_decay` | 0.05 | 0.01 … 0.1 | только на матрицы |
| `lamb` | 0.05 | 0.02 … 0.1 | главный рычаг |
| `inv_weight` | 0.5 | 0.1 … 1.0 | вес inverse-dynamics |
| `metric_weight` | 1.0 | 0.5 … 2.0 | вес метрической регуляризации |
| `probe_weight` | 1.0 | 0.5 … 2.0 | вес пробы `z → p` |
| `ctx` | 2 | 2 … 4 | без истории нет скорости |
| `batch_size` | 32 | ≥ 32 | SIGReg шумит на малых батчах |
| `sigreg_slices` | 256 | 64 … 512 | больше — точнее, дороже |
| `warmup` | 5% шагов | 1 … 10% | стабилизирует старт |
| `grad_clip` | выключен | — | не нужен по теореме 4 |
| `amp` | bf16 | — | SIGReg считается в fp32 |

### 5.5 Как выбрать `λ`

`λ` — единственный настоящий гиперпараметр. Логика:

* **слишком мал** (`<0.01`): предсказание доминирует → эмбеддинги сжимаются →
  коллапс или почти-коллапс;
* **слишком велик** (`>0.2`): SIGReg доминирует → модель тратит ёмкость на
  «расталкивание», предсказание деградирует;
* **рабочий диапазон** `0.02–0.1` работает без подбора на разных архитектурах
  (это заявленное свойство LeJEPA).

В нашем конфиге `0.05`.

## 6. Диагностика: что смотреть

### 6.1 Шесть кривых

```
pred_loss   ── должна плавно падать
inv_loss    ── должна падать: латент сохраняет управляемые факторы
probe_loss  ── должна падать: латент содержит физические координаты
metric_loss ── должна падать к 0: латент становится метрикой
sigreg_loss ── должна держаться в узком коридоре (не 0, не взрыв)
val_pred    ── должна идти рядом с train pred_loss
```

### 6.2 Таблица симптомов

| Симптом | Вероятная причина | Что делать |
|---|---|---|
| `sigreg → 0` | коллапс | увеличить `λ`, увеличить батч, проверить BN в проекторе |
| `sigreg` растёт и не падает | `λ` слишком велик / lr велик | уменьшить `λ` или lr |
| `pred_loss` стоит на месте | предиктор недообучен / нет контекста | `ctx ≥ 2`, увеличить `pred_hidden`/`depth`, lr |
| `pred_loss` падает, но планирование не работает | латент выбросил управляемые факторы | `inv_weight` ↑, `tools/probe_latent.py` |
| `inv_loss` не падает | голова недообучена или действия не влияют на среду | увеличить `inv_weight`, проверить среду |
| `metric_loss` не падает | конфликт с SIGReg при `D ≫ k` | уменьшить `proj_dim` (см. §8) |
| `probe_loss` не падает | латент не содержит координат | увеличить `probe_weight`, `proj_dim` ↑ |
| `probe_latent` показывает `noise > 0.05` | латент высокочастотный | `proj_dim` ↓, размытие входа |
| `pred_loss` падает, `val_pred` растёт | переобучение **или** рассогласование BN | `recalibrate_bn()`, потом уже weight decay |
| `val_pred` в разы хуже train | BN-статистики устарели | `recalibrate_bn()` |
| loss скачет | батч мал, bf16 шумит | батч ≥ 64, SIGReg в fp32 |
| всё нормально, но планирование не работает | латент не отражает управляемые факторы | проверить, что действия действительно влияют на среду |

### 6.3 Проверка на коллапс (быстрая)

```python
z = model.encode_sequence(frames)        # (B,T,D)
z = z.reshape(-1, z.shape[-1])
print("std по осям:", z.std(0).min().item())   # должно быть > 0.1
print("norm:", z.norm(dim=-1).mean().item())   # не должна улетать в десятки
print("rank:", torch.linalg.matrix_rank(z - z.mean(0)))  # близко к D
```

Если `min(std) ≈ 0` — часть осей мертва. Если `rank << D` — размерный коллапс.
Если норма латента в `eval()` в разы больше, чем в `train()` — устарели
BN-статистики (см. §8, «а2»).

## 7. Масштабирование и DDP

SIGReg идеально ложится на распределённое обучение, потому что это
**усреднение по направлениям и по сэмплам**. Достаточно:

1. каждому процессу дать свой набор случайных направлений (или синхронизировать
   через `global_step`-сид);
2. сделать `all_reduce(mean)` статистики;
3. всё.

Никаких `all_gather` эмбеддингов (как в SimCLR) и никаких синхронизаций
BatchNorm (как в BYOL) не требуется. Память линейна по локальному батчу.

В нашем коде DDP не реализован — это один из пунктов `ROADMAP.md`.

## 8. Практические грабли

### 8.1 Нормировка в проекторе

**(а) BatchNorm — это не «эвристика», а защита от седловой точки.**
У SIGReg нулевой градиент в точке `z = 0`. Если сеть может уменьшить ошибку
предсказания, сжимая латент к нулю, она это сделает — и вытащить её оттуда
уже нельзя. BN нормирует признаки **по батчу**, поэтому «все сэмплы
одинаковые» становится недостижимым состоянием. Проверено: с `LayerNorm`
латент схлопывался (`std → 0.000`), с `BatchNorm` держится.

**(б) Но у BN есть цена: расхождение train/eval.**
BN хранит running-статистики. Пока модель учится, они устаревают. В
eval-режиме это даёт другой масштаб латента:

| режим | `pred_loss` | норма латента | `sigreg` |
|---|---|---|---|
| `train()` | 0.24 | 7.6 | 10.0 |
| `eval()` (без пересчёта) | **3.25** | **36.2** | **524** |

Ошибка в 13 раз, и — что хуже — инференс работает на «сломанном»
представлении. Решение — `recalibrate_bn()`: перед оценкой сбрасываем
running-статистики и прогоняем 8 обучающих батчей в `train()`-режиме.

**(в) Проба и другие головы должны учиться на eval-латентах.**
Даже после пересчёта BN латент в `train()` и `eval()` не идентичен. Проба,
обученная в `train()`, в инференсе ошибалась на 50 px вместо 2.
Решение — `calibrate_probe()`: замораживаем энкодер в `eval()`, дообучаем
только пробу.

Отсюда общее правило: **вспомогательная голова, которая используется на
инференсе, обязана обучаться на инференсных латентах.**

### 8.2 Прочее

**(г) SIGReg в bf16.**
Статистика — разность близких величин. В bf16 (8 бит мантиссы) она теряет
точность. Мы явно считаем в fp32: `self.sigreg(z.float())`.

**(д) Слишком «лёгкая» среда.**
На игрушечном мяче `pred_loss` падает до 0.003 — модель почти идеальна. Это
не значит, что метод работает на реальном видео. Для честной проверки нужны
среды с контактами, трением и неопределённостью.

**(е) `smooth_l1` вместо `mse`.**
MSE чувствителен к выбросам в латенте (особенно на старте). `smooth_l1`
даёт линейный рост на больших ошибках и квадратичный на малых.

**(ж) Не путайте `λ` с learning rate decay.**
Это разные вещи, и `λ` не нужно расписывать по шагам.

**(з) Нормируйте всё, что попадает в лоссы.**
Позиции в пикселях (0..64) давали потерю пробы ~30 и доминировали над
`pred_loss` 0.27. Нормировка в `[-1, 1]` приводит все члены к одному
масштабу. То же касается нулевой инициализации выхода пробы: иначе стартовая
потеря ~20.
