# 10. Оценка: как понять, что модель действительно понимает мир

## 1. Коротко

JEPA легко переоценить. Метрика «ошибка предсказания в латенте» может
улучшаться, пока система не научится ничему полезному: достаточно сделать
латент тривиальным.

Поэтому оценка идёт на **трёх уровнях**, и ни один из них не достаточен сам
по себе:

```
1. Представление   — геометрия латента
2. Предсказание    — точность и калибровка
3. Поведение       — успех в задачах
```

---

## 2. Уровень 1: качество представления

### 2.1 Что измеряем

| Метрика | Формула / смысл | Норма |
|---|---|---|
| **Rank** | ранг матрицы `Z - mean(Z)` | близко к `min(N, D)` |
| **Min std по осям** | `min_d std(Z[:,d])` | > 0.1 |
| **Alignment** | средняя близость `z` внутри пары | выше — лучше |
| **Uniformity** | логарифм среднего `e^{-2‖z_i-z_j‖²}` | ближе к −2…−4 |
| **Effective rank** | энтропия сингулярных чисел | > 0.5·D |

`alignment` и `uniformity` — из статьи Wang & Isola (2020), стандартный
набор для self-supervised.

### 2.2 Линейная проба

Заморозить энкодер, обучить линейный слой на размеченных данных. Это самый
честный тест: если информация есть, она линейно извлекается.

```python
z_train = model.encode(train_frames)      # (N, D), без градиентов
clf = LogisticRegression(max_iter=1000).fit(z_train, y_train)
acc = clf.score(model.encode(test_frames), y_test)
```

В LeJEPA именно так получены 79% на ImageNet-1k с ViT-H/14
[arXiv:2511.08544].

### 2.3 kNN-проба

Дешевле линейной: для каждого тестового `z` берём `k` ближайших обучающих
и голосуем. Не требует обучения, но чувствительна к метрике.

## 3. Уровень 2: предсказание

### 3.1 Точность

```python
pred_loss = smooth_l1(Pred(z_t, a_t), z_{t+1})
```

Важно смотреть **на отложенных траекториях** и **на нескольких горизонтах**:

| Горизонт | Что проверяет |
|---|---|
| 1 шаг | локальная динамика |
| 4 шага | инерция, причинность |
| 16 шагов | долгосрочная согласованность |

Если ошибка на 1 шаге мала, а на 16 растёт взрывно — модель выучила
«локальный тренд», а не динамику.

### 3.2 Калибровка (surprise)

Ошибка предсказания должна коррелировать с реальной неожиданностью.
Проверка:

1. собрать «нормальные» и «аномальные» последовательности;
2. посчитать `surprise` для каждой;
3. измерить AUC.

Хорошая модель: AUC > 0.8. Это же свойство используется для детекции
аномалий и для переключения System 1 / System 2.

### 3.3 Интуитивная физика

Бенчмарки, которые прямо проверяют «понимание мира»:

| Бенчмарк | Что проверяет | Результат современных моделей |
|---|---|---|
| **IntPhys 2** [arXiv:2506.09849] | постоянство, неизменность, непрерывность, твёрдость | большинство ≈50% (случайно), люди почти 100% |
| **Physion** [arXiv:2106.08261] | предсказание развития сцены | модели заметно хуже людей |
| **Physion++** [arXiv:2306.15668] | латентные свойства (масса, трение, упругость) | модели не выводят свойства сами |

Ключевой вывод: **эти бенчмарки всё ещё не решены**. Любая система, которая
их проходит, заслуживает внимания.

## 4. Уровень 3: поведение

### 4.1 Успех в задачах

```python
success = (dist(final_state, goal) < tolerance)
```

Для нашего toy: `dist < 3·radius` (см. `runtime/cli.py::cmd_eval`).

Обязательно указывать:

* число эпизодов;
* разброс (std, а не только среднее);
* seed'ы;
* распределение целей.

«Success 73%» без этих деталей — не результат.

### 4.2 Эффективность по данным

Главный аргумент JEPA — не абсолютное качество, а **сколько данных нужно**.

```
sample_efficiency = качество / число обучающих примеров
```

В статье о платоновских представлениях: **42× меньше** примеров для того же
выравнивания [arXiv:2610.39302]. Проверять надо именно это отношение, а не
абсолютные числа.

### 4.3 Устойчивость к сдвигу

Тесты, которые надо прогнать обязательно:

| Сдвиг | Что меняем | Ожидание |
|---|---|---|
| цвет | оттенок объекта | качество не падает |
| фон | текстура сцены | качество не падает |
| освещение | яркость/контраст | небольшое падение |
| масштаб | размер объекта | небольшое падение |
| камера | угол/высота | заметное падение (это уже другая задача) |

Если падение на цвете > 20% — модель выучила корреляцию, а не физику.

## 5. Как обмануть себя (и как не обмануть)

### 5.1 Пять классических ловушек

**(а) Утечка через seed.**
Обучающие и тестовые траектории сгенерированы одним `seed` → почти одинаковые.
В нашем `TrajectoryDataset` тест использует `seed + 991` — этого достаточно
для игрушки, но для реальных данных нужен split по сценам/дням/роботам.

**(б) Метрика в латенте вместо реальности.**
План может быть идеальным в латенте и провальным в среде. Всегда проверяйте
поведение.

**(в) Один seed.**
Разброс между seed'ами у маленьких моделей — 5–15 процентных пунктов.
Минимум 3 seed'а, лучше 5.

**(г) Подбор гиперпараметров на тесте.**
`λ` и `horizon` нельзя тюнить на том же наборе, где измеряете успех.

**(д) Сравнение с недотренированным baseline.**
«Наш метод лучше» часто означает «мы обучали дольше». Сравнивайте при
равном бюджете GPU-часов.

### 5.2 Минимальный протокол

```
для seed in [0, 1, 2]:
    обучить
    измерить: pred_loss (1/4/16 шагов), rank, success, robustness
отчитаться: mean ± std по seed'ам
```

## 7. Метрики, которые врут

| Метрика | Почему врёт |
|---|---|
| «loss упал» | можно упасть в коллапс |
| «параметров меньше» | не говорит о качестве |
| «обошли модель в 600 раз больше» | обычно на одном узком тесте |
| «человекоподобное поведение» | легко имитируется без понимания |
| «модель уверена» | уверенность ≠ калибровка |

Особенно про «в 600 раз больше»: в статье 109M-модель обошла 72B **только**
в тесте на согласованность представлений текста и изображений. В математике,
коде и ответах на вопросы она не сравнивалась. Это надо повторять каждый раз,
когда цитируете результат.
